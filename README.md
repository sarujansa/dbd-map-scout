# DbD Map Scout

*[English version: README.en.md](README.en.md)*

Map-Overlay für Dead by Daylight. Beim Match-Start wird der Map-Name automatisch erkannt und die passende Callout-Karte aus dem Ordner `maps/` eingeblendet. Die Karte liegt als eigenes, durchklickbares Fenster über dem Spiel.

**Sprache:** Das Programm zeigt Deutsch oder Englisch. Standardmässig richtet es sich nach der Windows-Sprache (Deutsch, wenn Windows auf Deutsch läuft, sonst Englisch). Umstellen unter **Einstellungen → Sprache und Darstellung → Sprache / Language**; wirkt nach dem nächsten Start.

## Installation (einmalig)

1. **Python installieren** (falls noch nicht vorhanden): <https://www.python.org/downloads/>, Version 3.12 oder neuer. Im Installer **„Add python.exe to PATH“** anhaken.
2. Ordner entpacken, z. B. nach `C:\Tools\dbd-map-scout`.
3. **`start.bat`** doppelklicken. Beim ersten Start wird eine eigene Python-Umgebung (`.venv`) angelegt und die Pakete werden installiert (ca. 1–2 Minuten, rund 250 MB). Danach startet das Programm direkt.
4. **Desktop-Verknüpfung:** Läuft das Programm einmal als Administrator (z. B. Rechtsklick auf `start.bat` → „Als Administrator ausführen“), richtet es sie **selbst** ein und erneuert sie nach Updates oder wenn du den Ordner verschiebst. Von Hand geht es mit **`verknuepfung_erstellen.bat`** (Windows fragt einmal nach Administratorrechten). Beides legt in der Windows-Aufgabenplanung die Aufgabe „DbD Map Scout“ an und „DbD Map Scout“ mit eigenem Symbol auf den Desktop: Die Verknüpfung startet das Programm als Administrator (nötig für „Verbunden mit“) **ohne Windows-Abfrage** und ohne Konsolenfenster. Dieselbe Verknüpfung kommt ins **Startmenü**. Anheften geht über die Verknüpfung (Rechtsklick → „An Taskleiste anheften“) oder direkt am laufenden Programm in der Taskleiste – beides ist dann ein Knopf mit dem Programmsymbol. (Vor 1.30.3 angeheftet und es zeigt das Python-Symbol? Einmal „Von Taskleiste lösen“, Programm einmal über die Desktop-Verknüpfung starten, neu anheften.)

**Infobereich und Autostart.** Minimiert verschwindet das Steuerfenster in den Infobereich neben der Uhr (Doppelklick öffnet es, Rechtsklick: Overlay ein/aus, Beenden). Das Programm **startet mit Windows** (seit 1.30.3 standardmäßig, eingerichtet beim ersten Start als Administrator bzw. über die Desktop-Verknüpfung) – still im Infobereich, als Administrator, ohne Abfrage. Ohne DBD sucht es nur einmal pro Sekunde nach dem Spielfenster; sobald DBD läuft, arbeitet es. Direkt „beim Start von DBD“ geht nicht regelkonform (dafür müsste etwas die Prozesse überwachen oder das Spiel starten). Läuft es schon (auch unsichtbar im Infobereich), meldet ein weiterer Start nur „läuft bereits“. Abschalten unter **Einstellungen → Start und Infobereich** – dann bleibt es aus. Das Umschalten geht, wenn das Programm über die Desktop-Verknüpfung läuft.

*Zur Sicherheit:* Eine Aufgabe „mit höchsten Rechten“ umgeht die Windows-Abfrage absichtlich – was im Programmordner liegt (auch per Update geholter Code), läuft dann ohne Nachfrage als Administrator. Wer das strenger will, legt den Ordner an einen Ort, in den nur Administratoren schreiben dürfen (z. B. unter `C:\Program Files`).

**Updates** kommen automatisch: Beim Start über `start.bat` bzw. die Desktop-Verknüpfung holt das Programm den neuen Stand von GitHub (nur wenn der Ordner ein Git-Klon auf `main` ist und du keine Programmdateien selbst geändert hast) und installiert geänderte Pakete nach. Offline oder bei eigenen Änderungen startet einfach die vorhandene Version. Was neu ist, steht danach im Log. Abschaltbar unter **Einstellungen → Updates**. Dort gibt es auch **„Jetzt nach Updates suchen“**: fragt GitHub (nur bei diesem Klick), zeigt „Kein Update“ oder die neue Version mit ihren Änderungen, und **„Aktualisieren und neu starten“** beendet das Programm, installiert das Update über `start.bat` und startet neu – auch wenn die Prüfung beim Start ausgeschaltet ist.

In DBD unter **Einstellungen → Grafik** den Anzeigemodus **„Fenster-Vollbild“** verwenden. Im exklusiven Vollbild kann Windows kein Fenster über dem Spiel anzeigen.

**Fenstermodus** geht auch: Die Karte erscheint dann neben dem DBD-Fenster, wenn auf dem Monitor daneben mindestens 200 px frei sind, und die Fensteraufnahme im Hintergrund rechnet die Titelleiste heraus. Kleiner als 1920×1080 ist die Erkennung unsicherer (vor allem Lobby-Knopf und Killername). Fenster schmaler als 16:9 (z. B. 1718×1360): DBD zeigt das Match dort mit schwarzen Balken oben und unten, das Spielbild ist nur gut 850 px hoch. Der Map-Name wird seit 1.44.1 auch dann gelesen (die feine Linie unter dem Namen ist bei so kleinem Bild sehr blass); Rundenende und Lobby sind in diesem Format weniger erprobt. **Ab 1.45 nutzt Map Scout diese Balken:** Die Karte kommt dann in den unteren Balken (seit 1.45.1 auch bei eigener Position – die gilt wieder, sobald keine Balken oben/unten da sind, z. B. im Vollbild) (links, Timer/Server rechts daneben), die Systemwerte in den oberen. Die Balken werden im laufenden Bild gemessen (im Intro mit dem Map-Namen sind sie höher als im Spiel). In Lobby und Menüs gibt es keine Balken, dort gilt die normale Platzierung. Die Karte ist so groß, wie der Balken hoch ist – bei 1718×1360 etwa 170 px. Beides meldet das Log einmal.

## Benutzung

Beim **ersten Start** führt eine kurze **Einrichtung** (seit 1.60) durch drei Schritte: Spielsprache, Overlay-Position (mit „Overlay testen“) und die wichtigsten Tasten – „Überspringen“ geht jederzeit, wieder öffnen unter Einstellungen → Start und Infobereich → „Einrichtung starten“. **Suche:** das Feld über der Navigation (Strg+F) findet jede Einstellung auf allen Seiten, springt hin und hebt den Kasten kurz hervor.

Programm starten und DBD spielen. Wenn beim Match-Start unten links der Map-Name erscheint (z. B. „KOHLELAGER / DAS MACMILLAN-ANWESEN“), wird die Karte automatisch eingeblendet.

**Nach der Runde** verschwindet die Karte wieder. Erkannt wird das an:

- dem Ergebnisbildschirm (Knopf „CONTINUE“/„FORTFAHREN“),
- Lobby, Hauptmenü, Blutnetz und Shop (Währungsanzeige oben rechts),
- dem Ladebildschirm der nächsten Runde (fast schwarzes, stilles Bild mit Ladebalken – am Boden liegend mit Aufsteh-Balken zählt nicht),
- einem geschlossenen DBD.

Auf Ultrawide-Monitoren zeigt DBD Ergebnisbildschirm und Menüs in voller Breite, das Match aber in 16:9 mit schwarzen Balken. Das Programm erkennt das und sucht CONTINUE und Währungsanzeige dann bis zum echten Bildschirmrand; im Match bleiben die Balken außen vor.

**In Menüs pausiert das Overlay.** DBD zeigt den Mauszeiger nur in Menüs (ESC-Menü, Ergebnisbildschirm, Lobby). Ist er ein paar Sekunden lang über dem DBD-Fenster sichtbar, blendet sich die Karte aus. Verschwindet er wieder, kommt sie zurück. Ist der Mauszeiger insgesamt eine Minute lang in einem Menü sichtbar, gilt die Runde als beendet.

**Rundentimer.** Der Timer läuft, solange eine Karte eingeblendet ist. Erscheint eine Karte (automatisch erkannt, manuell gewählt oder per Hotkey eingeblendet), beginnt er bei 00:00. Verschwindet sie (Rundenende erkannt oder manuell ausgeblendet), stoppt er. Er steht im Steuerfenster unter dem Map-Namen („Runde läuft: 07:32“, danach „Letzte Runde: 12:04“) und im Overlay groß und mittig direkt unter der Karte, gestaltet wie der Kartentitel: weiße Ziffern mit Schatten, ohne Kasten (abschaltbar im Tab Overlay). Beim Rundenende zählt der erste Hinweis darauf als Endzeit, z. B. das Erscheinen des Mauszeigers auf dem Ergebnisbildschirm, nicht erst der Moment, in dem die Erkennung sicher ist. Das kurze Ausblenden im ESC-Menü oder wenn ein anderes Fenster aktiv ist, hält den Timer nicht an, weil das Match weiterläuft. Ein Layout- oder Map-Wechsel bei eingeblendeter Karte setzt ihn nicht zurück. Ein neues Map-Banner startet immer eine neue Runde, auch wenn das Ende der vorigen nicht erkannt wurde.

**Wartekarte.** Läuft DBD und ist gerade keine Karte eingeblendet (vor dem Match, in der Lobby, nach der Runde), zeigt das Overlay an derselben Stelle eine kleine Karte: „WARTE AUF MAP“, darunter die Suche bzw. Lobby („SUCHE LÄUFT: 02:13 · NURSE“) oder nach der Runde „LETZTE RUNDE: 12:04“. Ist „Verbundener Spielserver“ (Tab Server) an, stehen darunter Region und Ping, sobald DBD mit einem Spielserver verbunden ist – in der Regel ab der Lobby. Sobald das Map-Banner erkannt ist, ersetzt die Karte sie. Steht sie mitten im Match noch da, wurde die Map nicht erkannt – dann „Scannen“. Nicht, wenn du die Karte selbst ausgeblendet hast; abschaltbar im Tab Overlay.

**Nur mit laufendem DBD.** Solange das DBD-Fenster nicht gefunden wird, erkennt das Programm nichts automatisch, auch wenn auf dem Bildschirm ein DBD-Video oder Screenshot zu sehen ist. So erscheint beim Arbeiten keine Karte. „Scannen“ prüft auf Klick trotzdem den Hauptbildschirm.

Im Tab **Erkennung** zeigt die Zeile „Rundenende-Erkennung: …“ jederzeit, was das Programm gerade sieht, z. B. „im Match · Mauszeiger verborgen“. `Strg+Alt+M` holt eine ausgeblendete Karte sofort zurück.

Oben im Steuerfenster steht immer, woran das Programm gerade ist: **Wartet auf DBD**, **Wartet auf das nächste Match**, **Im Match: …**, **Im Menü – Karte pausiert** oder **Runde vorbei** (Probleme wie ein schwarzes Bild stehen dort in Rot). Technische Einzelheiten stehen im Tab Log.

**Hinweistexte:** Bleibt die Maus kurz auf einem Knopf oder Häkchen, erklärt ein kleiner Text, was er tut (samt Hotkey).

**Layout-Knopf:** Erscheint nur bei Maps mit mehreren Layouts (Coal Tower, Groaning Storehouse, Ironworks of Misery, Shelter Woods, Suffocation Pit, Mount Ormond Resort, Badham Preschool) und zeigt das angezeigte Layout, z. B. „Layout II von V ▸“. Ein Klick schaltet weiter. War die Erkennung beim Layout unsicher, steht „(unsicher)“ dahinter.

Das Steuerfenster ist in Tabs aufgeteilt. Passt ein Tab nicht ins Fenster, erscheint rechts eine Scrollbar (auch per Mausrad); das Fenster lässt sich dafür beliebig kleiner oder grösser ziehen:

| Tab | Inhalt |
|---|---|
| **Maps** | alle Karten nach Realm, Suche, rechts eine **Vorschau** der gewählten Karte (seit 1.58.1; die gerade gezeigte Map ist aufgeklappt und markiert), Doppelklick oder „Anzeigen“ blendet sie ein; „Kartenbild hinzufügen …“ für eigene Bilder |
| **Overlay** | Position (Vorgabe oder Schieberegler horizontal/vertikal, 0 % = links/oben, 100 % = rechts/unten; Regler bewegen schaltet auf „eigene Position“), „Overlay testen“, Grösse, Deckkraft, Anzeigeoptionen |
| **Statistik** | oben die Filter und die Knöpfe „Stats-Seite öffnen“/„Verlauf löschen“, darunter Unter-Reiter über die ganze Höhe des Fensters (seit 1.58.1 – vorher standen Dashboard und Knöpfe über den Tabellen und liessen ihnen ein paar Zeilen; der Tag auf einen Blick steht in der **Übersicht**). Unter-Reiter **System** (seit 1.60 übersichtlicher): Kacheln mit den Durchschnitten (GPU-/CPU-Temperatur, GPU-Last, Leistung, Drosselung), Höchstwerte als Tabelle mit Wann/Map, darunter die Aufteilung nach Map/Uhrzeit/Wochentag/Killer und der Temperaturverlauf. Der erste Unter-Reiter **Übersicht** ist das **Dashboard** (seit 1.58) für die gewählten Filter: Kacheln (Runden und Spielzeit, Ø Kills mit 4K und Abandons, Entkommen, Ø Rundendauer, Ø Wartezeit, Ø Bloodpoints), die **meistgespielten Maps** als Balken mit Ø Kills/Entkommen und **Killer × Map** als Heatmap (Ø Kills laut Stats-Seite je Killer und Map; Felder mit weniger als 2 Runden bleiben leer, beim Überfahren Wert und Rundenzahl). Die weiteren Unter-Reiter zeigen deine Runden als Tabellen ( Maps – je Map auch getrennt nach Killer/Survivor –, Killer, Serverregionen, Wartezeit, Letzte Runden), filterbar nach Zeitraum (heute, diese Woche, dieser Monat, dieses Jahr) und Serverregion: Anzahl, Ø Dauer, Gesamtzeit; pro Map Runden, Killer/Survivor, Ø Kills, Entkommen, Ø Dauer und Ø Bloodpoints (Spalten anklickbar zum Sortieren); pro Serverregion Runden, Ø Dauer, Anteil und Ø Ping (Median je Runde, nur mit „Verbundener Spielserver“); die letzten 100 Runden mit Datum, Dauer und Serverregion. Gezählt wird vom erkannten Map-Banner bis zum erkannten Rundenende (ab 1 Minute; ohne erkanntes Ende wird die Runde nicht gezählt). Zusätzlich filterbar nach **Rolle** (Killer, Survivor, Custom Games) und mit **Wartezeit in der Lobby**: Ø, Median, kürzeste und längste Suche, aufgeteilt nach Wochentag, Uhrzeit (3-Stunden-Blöcke) oder Region. Als Killer merkt sich jede Runde auch den **Killer** (Name unter dem Lobby-Knopf; seit 1.61 zählt auch ein knapp falsch gelesener Name wie „Hillilly“ für den Killer, auch rückwirkend): eigene Tabelle mit Runden, Ø Dauer und häufigster Map je Killer, und Filter **Killer** – z. B. welche Maps du mit der Nurse wie oft bekommst und wie lange die Runden dauern. Lag die Rollenerkennung daneben: Runde unter „Letzte Runden“ markieren und mit **Killer / Survivor / Custom Game** korrigieren; eine falsche Runde entfernt **Runde löschen** (fragt vorher nach). Wurde das Ende einer Runde nicht erkannt, zählt sie nicht – die Statistik sagt dann „⚠ Nicht gezählt: 2 × …“, damit du weisst, dass Runden fehlen. Kills, Escapes und Bloodpoints kommen aus den offiziellen Match-Daten (siehe unten), ebenso der Unter-Reiter **Verlauf**: Ø Kills als Killer und Escape-Quote als Survivor als Säulen pro Woche (bei „Dieser Monat“/„Diese Woche“ pro Tag, bei „Heute“ pro Stunde); die Maus über einer Säule zeigt Wert und Anzahl der Runden. Nur lokal in `rounds.jsonl`, „Verlauf löschen“ entfernt alles |
| **Server** | oben der verbundene Spielserver, darunter Serverregionen mit Ping, per hosts-Datei sperren oder freigeben (siehe unten) |
| **Einstellungen** | Hotkeys ändern, Benachrichtigungen, Start/Infobereich, Sprache, Dark Mode, Schriftgröße, Updates; eingeklappt unter „Mehr“: eigene Map-Zuordnungen, Sicherung, Ordner öffnen. **Farbthemen** (seit 1.62, Einstellungen → Sprache und Darstellung): Gold (Standard), Blutrot, Eisblau, Giftgrün und Lila – jeweils dunkel und hell, dazu der Schalter **OLED-Schwarz** (seit 1.62.1, echtes Schwarz statt Grau im Dark Mode, mit jeder Farbe kombinierbar); alle auf Lesbarkeit geprüft. **Farbpalette und eigene Farbe** (seit 1.63): unter dem Farbthema 14 Farbfelder zum Anklicken und „Eigene Farbe …“ für jede beliebige Farbe – das Programm verschiebt nur die Helligkeit, bis Schrift und Knöpfe in Dark, Hell und OLED lesbar sind (im hellen Modus wird z. B. Gelb zu Ocker). **„Heute“ im Balken** (seit 1.62, Tab Overlay → Systemwerte): unter den Systemwerten oben im schwarzen Balken Runden und Spielzeit heute, Ø Kills bzw. Entkommen laut Stats-Seite und die Uhrzeit – auch ohne Systemwerte (dann rechts oben). **„Läuft gerade“** (seit 1.64): Titel, Interpret und Albumcover der Musik, die gerade spielt (Spotify, YouTube im Browser … – alles, was Windows beim Lautstärkeregler anzeigt), nur solange sie läuft. Eigene Karte mit wählbarer Position (unter den Systemwerten, rechts oder links unten im Balken, oder frei: im Modus „Mit der Maus verschieben“ ziehen), Größenregler 60–200 % und Häkchen fürs Cover (Tab Overlay → Systemwerte). Nur Anzeige: Das Programm steuert die Musik nicht, speichert nichts und schreibt den Titel weder ins Log noch in die Diagnose. **Overlay-Vorschau** (seit 1.61, Tab Overlay → Position): dein Bildschirm mit Spielbild und schwarzen Balken, darauf die Karte so groß, durchsichtig und an der Stelle, wo sie im Spiel erscheint – Größe, Deckkraft und Häkchen wirken sofort. Seit 1.64.1 zeigt sie **jedes Element so, wie es im Spiel aussieht**: Karte mit Timer/Bilanz/Server, Systemwerte mit „Heute“ und die Musikkarte mit Cover (läuft nichts, ein Beispiel-Lied) – gezeichnet mit denselben Funktionen wie im Spiel; jeder Regler und jede Position ist sofort darin zu sehen. **Verschieben** (seit 1.64.2): Knopf „Mit der Maus verschieben“ drücken (auch ohne Map) – dann lassen sich Karte, Systemwerte/„Heute“ und Musikkarte in der Vorschau anfassen und ziehen (Klick auf eine freie Stelle setzt die Karte dorthin), im Spiel ebenso; „Fertig“ beendet es. Außerhalb dieses Modus verschiebt ein Klick in der Vorschau nichts. Ist gerade keine Map eingeblendet, zeigt das Programm zum Verschieben eine Testkarte (auch im Spiel) und blendet sie mit „Fertig“ wieder aus (seit 1.64.3). Klicken oder Ziehen in der Vorschau setzt die Karte dorthin (eigene Position, im Balken gehalten, solange „Im schwarzen Balken halten“ an ist). **Server:** die Knöpfe „Ping messen / Auswahl anwenden / Alles freigeben“ stehen über der Liste. **Schmales Fenster** (seit 1.59.1): Zeilen und Kacheln brechen um, statt abgeschnitten zu werden; unter 960 px Breite zeigt die Navigation links nur Symbole (Name beim Überfahren). **Eigene Anordnung** (seit 1.59): Die Kästen der Seiten Overlay, Einstellungen, Server und Erkennung lassen sich am Griff (⋮⋮ rechts im Titel) nach oben oder unten ziehen – z. B. „Updates“ ganz nach oben; das Programm merkt sich die Reihenfolge, „Anordnung zurücksetzen“ (Sprache und Darstellung) stellt alles zurück. Seit 1.62.2 springt die Seite beim Klick auf einen Knopf in einem verschobenen Kasten (z. B. „Jetzt nach Updates suchen“) nicht mehr nach unten, und die Tab-Taste folgt der eigenen Reihenfolge |
| **Erkennung** | Automatik, Ausblenden nach der Runde, Pause in Menüs, Spielsprache; eingeklappt unter „Erweitert“: Fensteraufnahme, Scans pro Sekunde, Live-Status, Debug-Bilder, Diagnose |
| **Log** | Meldungen mit Kategorien *Erkennung*, *Overlay*, *System*, *Fehler*, einzeln ein-/ausblendbar |

**Position „automatisch“:** Läuft DBD mit 16:9-Bild auf einem breiteren Monitor (z. B. 3440×1440 mit schwarzen Rändern), landet die Karte im linken schwarzen Rand und wird so skaliert, dass sie hineinpasst. Im Fenstermodus erscheint sie neben dem DBD-Fenster (links, sonst rechts), wenn dort mindestens 200 px frei sind. Sonst erscheint sie oben links im Spielbild. Sobald du einen Positions-Regler bewegst oder die Karte mit der Maus verschiebst, gilt „eigene Position“. „Zurücksetzen“ stellt wieder „automatisch“ ein.

**Wartezeit und Rolle:** Außerhalb des Matchs schaut das Programm einmal pro Sekunde auf den Knopf unten rechts in der Lobby. CANCEL mit „EST.“ darunter heißt: Die Suche läuft (DBD zeigt die bisherige Wartezeit selbst an, die wird übernommen). READY bzw. CANCEL ohne „EST.“ heißt: Die Lobby ist gefunden, die Wartezeit steht fest. Steht unter dem Knopf der Killername, spielst du Killer, sonst Survivor; steht gar nichts darunter, ist es ein Custom Game (keine Wartezeit) – außer direkt nach einer Suche oder in einer gefundenen Lobby: Dort zeigt DBD READY ohne Countdown, bis der Timer startet (bzw. wenn jemand die Lobby verlässt); seit 1.64.4 zählt das richtig als Lobby statt als Custom Game. Auf dem Ergebnisbildschirm bestätigen die Kategorien (BRUTALITY … bzw. OBJECTIVES …) die Rolle. Das Hauptfenster zeigt „Suche läuft: 02:13 · Nurse“ bzw. „Rolle: Nurse · Wartezeit 02:13“ (als Survivor „Survivor“). Der Killername wird mit einer Liste der Killer abgeglichen. **Legendäre Skins** zeigen dort ihren eigenen Namen (z. B. „Murderous Grizzly“ statt „The Oni“) – bekannte Skins zählen automatisch für ihren Killer (Murderous Grizzly, The Minotaur → Oni; Naughty Bear, Frank Stone → Trapper; Ferryman of the Underworld → Blight; Were-Elk → Huntress; Hunk → Legion; William Afton → Animatronic). Ein Skin oder neuer Killer, den das Programm nicht kennt, wird so übernommen, wie er dasteht – nie einem falschen zugeordnet; in der Statistik unter „Killer“ die Zeile markieren, Killer wählen, **Zuordnen** (gilt auch rückwirkend). Einzelne Runde falsch (z. B. als Survivor gezählt, obwohl du Killer warst): unter „Letzte Runden“ markieren, Killer wählen, **Killer setzen** – sie zählt dann als Killer-Runde mit diesem Killer. Eine abgebrochene Suche zählt nicht. Im Match wird nichts davon geprüft.

**Meldung, wenn die Lobby gefunden ist:** Hinweiston plus eigenes kleines Hinweisfenster unten rechts („Lobby gefunden – nach 04:12 – READY drücken.“; über allen Fenstern, nimmt keinem Fenster den Fokus, erscheint auch bei „Nicht stören“ – Windows-Meldungen würden dann verschluckt; „Meldung testen“ zeigt es), und eine Erinnerung, wenn der Lobby-Countdown unter 15 s fällt und READY noch nicht gedrückt ist. Standardmäßig nur, solange DBD nicht das aktive Fenster ist – du kannst also während der Suche etwas anderes machen. Abschaltbar unter Einstellungen → Benachrichtigungen. Es geht nichts ans Spiel. Erkannt werden die englischen Texte des Spiels.

**Nur Infos ohne Karte:** Im Tab Overlay „Karte anzeigen“ ausschalten – dann zeigt das Overlay bei Rundenbeginn nur Rundentimer, Serverregion und Ping (an derselben Stelle, im selben Stil). Erkennung, Ausblenden nach der Runde, Menü-Pause und Statistik laufen unverändert weiter.

**Kills, Escapes und Bloodpoints (offizielle Match-Daten):** Die offizielle Seite [stats.deadbydaylight.com](https://stats.deadbydaylight.com/) kennt deine letzten 30 Matches mit Map, Rolle, Charakter, Bloodpoints und dem Status jedes Survivors. Ein eigenes Userscript bringt diese Daten in die Statistik – das Programm selbst geht dafür nicht ins Internet und sieht nie deine Login-Daten. Einrichten (einmal):

1. Im Browser **Tampermonkey** (oder Violentmonkey) installieren.
2. Einstellungen → Mehr → Offizielle Match-Daten → **Userscript kopieren**, in Tampermonkey „Neues Skript erstellen“, alles ersetzen (Strg+A, Strg+V), speichern.
3. Auf stats.deadbydaylight.com mit dem Behaviour-Konto anmelden.
4. Optional dort **„Stats-Seite öffnen, wenn DBD beendet wird“** einschalten: Schliesst du DBD nach mindestens einer Runde, öffnet das Programm die Seite im Browser (nie während DBD läuft). Zwischendurch geht es mit Statistik → **Stats-Seite öffnen**.

Beim Öffnen der Seite speichert das Skript die Matches als `dbdmapscout-matches.json` in den Download-Ordner – nur wenn ein neues Match dabei ist, und nur Startzeit, Map, Custom Game ja/nein, Rolle, Charakter, Status, Dauer und BP (keine Namen anderer Spieler, keine Konto- oder Login-Daten; das Skript schickt nichts irgendwohin). Das Programm schaut alle 20 s in den Download-Ordner (nach dem Öffnen der Seite alle 3 s), übernimmt die Matches in `official.jsonl` und **löscht die Datei** – ein kleines Hinweisfenster unten rechts meldet das („30 Matches gelesen, davon 4 neu. Die Datei wurde gelöscht.“ und darunter die neuen Matches: „Killer: Ø 3.1 Kills, 2× 4K (4)“, Escapes als Survivor, Bloodpoints – ohne Custom Games; nicht, solange DBD im Vordergrund ist; abschaltbar unter Einstellungen → Mehr → Offizielle Match-Daten). **Eigene Bilanz im Overlay:** Unter dem Rundentimer steht, wie es dir auf der erkannten Map bisher ging – als Killer „Ø 2.8 Kills · 12 Runden“, als Survivor „40 % entkommen · 9 Runden“ (Rolle aus der Lobby, sonst die auf der Map häufigere; ab 3 Runden mit Daten der Stats-Seite; abschaltbar im Tab Overlay). Dateien mit diesem Namen, aber ohne die Kennung des Programms bleiben liegen. Zugeordnet wird über Map und Startzeit (das Map-Banner kommt etwa 30–50 s nach dem Start laut Seite).

Die Statistik bleibt eine Statistik **deiner Runden** – die offiziellen Daten ergänzen nur die Runden, denen ein Match zugeordnet ist. Unter der Rundenzahl stehen Ø Kills, 4K und Abandons als Killer, die Escape-Quote als Survivor und die Bloodpoints, jeweils mit der Zahl der Runden, aus denen sie stammen. Die Map-Tabelle zeigt dazu pro Map Ø Kills, Entkommen und Ø BP, die Killer-Tabelle Ø Kills und 4K, „Letzte Runden“ die Spalte **Ergebnis** (3K / entkommen / tot / aufgegeben). Bei zugeordneten Runden gilt der Killer laut Seite (Skins stimmen so automatisch), Custom Game laut Seite und – wenn die Erkennung danebenlag – auch die **Map laut Seite** (Layout I; andere Layouts gibt es seit Patch 8.6.0 nur in Custom Games). Runden, deren Ende das Programm nicht erkannt hat („⚠ Nicht gezählt“), zählen wieder, sobald es dazu ein Match gibt – mit der Dauer laut Seite. **Aufgeben (Abandon)** zählt für den Killer als Kill (wie in seinem Ergebnis im Spiel) und als Survivor nicht als entkommen; die Seite selbst zeigt manche Abandons fälschlich als „Escaped“, das Programm erkennt sie am Symbol. Wer das Match verlassen hat, zählt nicht als Kill.

Wie gut das Programm selbst arbeitet, steht im Tab **Erkennung → Abgleich mit der Stats-Seite**: die Erkennungsquote („Vom Programm erkannt: 29 von 30“) mit den zuletzt nicht erkannten Matches (Map und Uhrzeit), wie genau das Rundenende erkannt wird (Median gegenüber dem Ende laut Seite) und Hinweise bei einer **Lücke** (mehr als 30 Matches zwischen zwei Besuchen der Seite), bei **anderer Map als erkannt** und bei **unbekanntem Status** (die Statusnamen der Seite sind nicht dokumentiert; ein neuer Status zählt nicht, bitte mit „Diagnose kopieren“ melden). Fragt der Browser vor jedem Download nach dem Speicherort, kommt jedes Mal ein Dialog. Liegt der Download-Ordner woanders, in `settings.json` `official_dir` setzen.

**Mitten in der Runde** zeigt DBD nie ein Map-Banner – leuchtende Streifen oder Schilder in der Spielwelt können aber so aussehen. Ab 30 s nach dem Einblenden der Karte schaltet das Programm deshalb nur noch um, wenn das „Banner“ mindestens 2 s still steht und sauber gelesen wird (ein echtes Banner nach einem verpassten Rundenende schafft das). Alles andere landet nur als Zeile im Log („Mitten in der Runde … gelesen – ignoriert“), und „Diagnose kopieren“ listet unter „Letzte Banner“ jede Sichtung mit dem gelesenen Text. Von jeder solchen Sichtung legt das Programm ausserdem ein Bild in `debug/midmatch/` ab (auch ohne „Debug-Bilder speichern“; nur die letzten 20, höchstens eins alle 10 s) – damit lässt sich sehen, was es für ein Banner gehalten hat. Schaltet es trotzdem einmal mitten im Match um, sortiert die Statistik diese Runde aus, sobald die Daten der Stats-Seite da sind: Eine zweite „Runde“ mitten in einem Match, das schon einer Runde gehört, zählt nicht („✓ 1 × Map mitten im Match falsch erkannt …“). Ohne diese Daten: Runde unter „Letzte Runden“ markieren → **Runde löschen**.

**Unsichere Erkennung:** Echte Map-Banner passen fast perfekt auf einen bekannten Namen. Passt keines der gelesenen Bilder gut (Passung unter −3) und auch 2,5 s später nicht, zeigt das Overlay unter der Karte in Gelb „? UNSICHER – STRG+ALT+X = FALSCH“, und im Hauptfenster erscheint eine Leiste mit **Falsch erkannt** / **Stimmt**. „Falsch erkannt“ (oder `Strg+Alt+X`, geht bei jeder automatisch erkannten Map) blendet die Karte aus, setzt den Timer zurück und zählt die Runde nicht; dasselbe Banner zeigt sie danach nicht noch einmal. Liest das Banner kurz danach doch sauber, verschwindet der Hinweis von selbst.

**Karte drehen:** Knopf **Drehen ↻** im Hauptfenster oder `Strg+Alt+R` dreht die angezeigte Karte um 90° im Uhrzeigersinn, damit sie so liegt, wie du dir die Map vorstellst. Die Drehung wird pro Map gemerkt (Tab Overlay: „Für diese Map zurücksetzen“). Der Map-Name über der Karte bleibt aufrecht; die Zahlen und Beschriftungen in der Karte drehen sich mit, weil sie Teil des Bildes sind. Alle mitgelieferten Karten haben den Namen oben im selben Stil; nur bei Midwich (animiertes GIF mit eigenem Hintergrund) dreht sich der Name mit. Eine Karte, die sich automatisch mit der Kamera dreht, gibt es nicht: Den Blickwinkel kennt nur das Spiel selbst, und dessen Speicher wird nicht gelesen.

**Etagen (Midwich):** Midwich hat zwei Etagen; das Overlay zeigt beide untereinander, oben über unten. Jede Etage ist dabei so groß wie sonst eine Karte – das Overlay wird dafür doppelt so hoch (höchstens 90 % der Bildschirmhöhe); im schwarzen Balken eines Ultrawide-Monitors ist ohnehin die Breite die Grenze, dort passen beide in voller Balkenbreite übereinander. Der Knopf **Etage ▸** im Hauptfenster (nur bei Karten mit Etagen sichtbar) oder `Strg+Alt+F` schaltet um: beide → unten → oben → beide; das gilt bis zur nächsten Map. Der Knopf zeigt, was gerade zu sehen ist („Beide Etagen“ bzw. „Etage 2 von 2“). Soll Midwich nur mit der unteren Etage starten, im Tab Overlay „Etagen (Midwich) untereinander zeigen“ abschalten. Welche Etage du gerade betrittst, erkennt das Programm nicht (dafür müsste es den Spielspeicher lesen).

**Im schwarzen Rand halten** (Tab Overlay, standardmäßig an): Auf Ultrawide bleibt die Karte bei jeder Position im Balken, in dem sie liegt – „oben/unten links“ im linken, „oben/unten rechts“ im rechten Balken, eine eigene Position in dem Balken, in dem sie beginnt. Ist sie zu breit, wird sie verkleinert, statt ins Spielbild zu ragen. Eine bewusst mitten über dem Spiel platzierte Karte bleibt unverändert. Abschalten, wenn die Karte grösser sein darf als der Rand.

Das Overlay ist ein eigenes, natives Windows-Fenster: immer im Vordergrund, durchklickbar, und es nimmt dem Spiel nie den Fokus weg.

**Erkennung, wenn andere Fenster über DBD liegen.** Normalerweise wird der Bildschirm aufgenommen – liegt ein anderes Fenster über DBD, sieht das Programm dieses Fenster. Ist DBD nicht das aktive Fenster, nutzt das Programm deshalb die **Fensteraufnahme von Windows** (Windows Graphics Capture, dieselbe Technik wie OBS „Fensteraufnahme“): Windows liefert das Bild des DBD-Fensters, egal was darüber liegt. Das Spiel wird dabei nicht angefasst. Ist DBD wieder 5 Sekunden aktiv, geht es zurück zur sparsameren Bildschirmaufnahme. Minimiert geht nichts. Abschaltbar im Tab Erkennung („Auch erkennen, wenn andere Fenster über DBD liegen“). Das nötige Zusatzpaket installiert `start.bat` beim nächsten Start einmalig; klappt das nicht, läuft alles wie bisher über die Bildschirmaufnahme. Windows liefert ein neues Fensterbild nur, wenn sich im DBD-Fenster etwas bewegt – in einem ruhigen Menü kommt manchmal keins. Dann nimmt das Programm den Bildschirm, aber nur die Teile, über denen kein anderes Fenster liegt (laut Fensterliste von Windows); verdeckte Teile werden ausgelassen statt gelesen. Vorher konnte ein Fenster über DBD (z. B. die eigene Statistik) als Map-Banner gelesen werden. Die Zeile „Aufnahme“ in der Diagnose zeigt, welche Quelle gerade genutzt wird, ob das letzte Bild trotzdem vom Bildschirm kam und wie oft verdeckt ausgelassen wurde.

**Steuerfenster (Qt):** Navigation links, rechts die Seiten **Übersicht** (aktuelle Map mit Bild, Realm und wie sie erkannt wurde, Rundenzeit, Server, Ping, Rolle/Killer, die Knöpfe Scannen/Drehen/Overlay ein-aus/Falsch erkannt/Layout/Etage, dazu **Heute**, die **Systemwerte** und die **letzten Runden**), **Maps**, **Overlay**, **Statistik**, **Server**, **Einstellungen**, **Erkennung** und **Log**. Farben Grau/Gold, hell oder dunkel (Einstellungen → Dark Mode), **Einstellungen → Schriftgröße** 90–150 %. Rückfragen wie „Verlauf löschen?“ erscheinen als Leiste oben im Fenster, Dateien wählt ein eigener Datei-Dialog. Größe und Position des Fensters merkt sich das Programm. Seit 1.57 ist das alte Tk-Fenster ganz entfernt (bis 1.56 als Rückfall wählbar); auch das Overlay und das Hinweisfenster laufen ohne Tk. Das Fenster braucht das Paket PySide6 (Qt, ca. 80 MB), das `start.bat` installiert; fehlt es, sagt eine Meldung beim Start warum.

**Einstellungen sichern:** Einstellungen → Sicherung → „Einstellungen exportieren …“ speichert alles (Hotkeys, Grösse und Drehung pro Map, eigene Map-Zuordnungen, Overlay, Regionen) in eine Datei, „… importieren …“ lädt sie wieder und startet das Programm neu. Die Statistik gehört nicht dazu.

Hotkeys lassen sich unter **Einstellungen → Hotkeys** ändern: Feld anklicken und die neue Kombination drücken (Esc bricht ab, Entf schaltet den Hotkey aus, „Standard“ stellt alle zurück). Buchstaben, Ziffern und Leertaste brauchen Strg oder Alt, damit der Hotkey nicht das normale Tippen (und DBD) blockiert; doppelt belegte Kombinationen werden abgelehnt. **Eine Taste allein** geht mit F1–F12, Numpad (0–9, +, −), Pause, Rollen, Einfg, Pos1, Ende und Bild↑/↓: Solche Hotkeys gelten nur, solange DBD das aktive Fenster ist – in allen anderen Programmen bleibt die Taste normal. DBD selbst bekommt die Taste dann nicht mehr, also eine nehmen, die du in DBD nicht belegt hast. F13–F24 gelten immer (praktisch für Maus-Seitentasten, die man in Logitech G Hub, Razer Synapse & Co. auf F13 legt). Alle Einstellungen landen in `settings.json`.

**Systemwerte:** Oben im schwarzen Rand stehen während des Matches CPU- und GPU-Temperatur, Auslastung, GPU-Leistung, VRAM und RAM (Temperatur grün/gelb/rot; CPU ab 80/90 °C, GPU ab 75/85 °C). Schrift wie die Map-Namen auf den Karten (Fira Sans ExtraBold), Bezeichnungen grau, Werte hell. Einstellbar im Tab Overlay → Systemwerte: rechts oben (Standard), **direkt über der Karte** (wandert mit der Karte mit, auch bei eigener Position; ist oben kein Platz, rutscht die Karte darunter bzw. die Werte stehen unter ihr; im halb so breiten Fenster mit Balken oben/unten stehen sie rechts neben der Karte im unteren Balken), links oben (die Karte rutscht dann darunter), **eigene Position** oder aus. Bei „eigene Position“ lässt sich die Anzeige mit „Mit der Maus verschieben“ (Strg+Alt+P) zusammen mit der Karte irgendwohin ziehen, die Position wird pro Fenster relativ gespeichert; im schmalen Fenster mit Balken oben/unten bleibt sie im oberen Balken. Die GPU-Werte kommen von NVIDIA-Karten über den Treiber (`nvml.dll`). Für die **CPU-Temperatur** braucht es [HWiNFO](https://www.hwinfo.com/) mit „Shared Memory Support“ (HWiNFO → Einstellungen; in der kostenlosen Version alle 12 Stunden neu einschalten). Windows selbst verrät die CPU-Temperatur nur über einen Kernel-Treiber – den lädt das Programm bewusst nicht (Anti-Cheat, von Microsoft gesperrte Treiber wie WinRing0). Mit HWiNFO gibt es auch bei AMD-/Intel-Grafik eine GPU-Temperatur, außerdem eine Zeile mit **Hotspot** und **GPU-Speicher** (Memory Junction) – die kritischeren Werte, sie laufen 10–20 °C über der Kerntemperatur (gelb ab 95 °C, rot ab 105 °C). **Drosselt die GPU** wegen Temperatur oder Hardware (NVIDIA), erscheint rot „GPU DROSSELT (TEMP.)“ bzw. „(HW)“. Die normale Strombegrenzung unter Volllast zählt nicht – sie ist bei Grafikkarten der Normalzustand. In Lobby und Menüs (dort nutzt DBD die volle Breite) ist die Zeile aus. **Statistik → System:** Pro Runde merkt sich das Programm Durchschnitt und Höchstwert (GPU/CPU-Temperatur, GPU-Last, Leistung, VRAM, RAM; nur solange die Anzeige an ist). Dort stehen der Durchschnitt der Auswahl, die Höchstwerte mit Datum, Uhrzeit und Map und eine Tabelle nach Map, Uhrzeit (3-Stunden-Blöcke), Wochentag oder Killer – so sieht man, auf welchen Maps oder zu welcher Tageszeit der PC am heißesten läuft. Die Filter oben (Zeitraum, Region, Rolle, Killer) gelten auch hier. Dazu: Spalten Hotspot max und „Gedrosselt“ (Sekunden), ein Hinweis „GPU gedrosselt in n von m Runden“ und darunter ein **Verlauf der GPU-Temperatur** (Ø pro Stunde/Tag/Woche je nach Zeitraum, Maus über einem Punkt zeigt Ø, Maximum, Hotspot und Rundenzahl). Steigt die Linie über Wochen langsam an, sind meist Staub, Wärmeleitpaste oder ein Lüfter schuld.

**Spielsprache:** Standardmässig werden englische und deutsche Map-Namen erkannt. Wenn DBD auf Französisch, Spanisch, Italienisch, Polnisch, Portugiesisch oder Türkisch läuft, die Sprache im Steuerfenster anhaken (Tab Erkennung). Das ist unabhängig von der Sprache des Programms selbst.

## Serverregion wählen (wie „Make Your Choice“)

Im Tab **Server** stehen alle Serverregionen von DBD (AWS GameLift) mit ihrem aktuellen Ping. Du hakst die Regionen an, auf denen du spielen willst, und drückst **Auswahl anwenden**. Alle anderen Regionen werden in der Windows-**hosts-Datei** gesperrt: Ihre Servernamen zeigen dann auf 0.0.0.0, DBD erreicht sie nicht und sucht Matches nur noch in den erlaubten Regionen. **Alles freigeben** entfernt die Sperren wieder.

- **Administratorrechte:** Die hosts-Datei ist eine Windows-Systemdatei. Deshalb fragt Windows beim Anwenden und beim Freigeben nach. Nur dieser Schreibvorgang läuft mit Administratorrechten, das Programm selbst nicht (außer du startest es als Administrator oder nutzt die Anzeige des verbundenen Servers, siehe unten).
- **DBD danach neu starten.** Die Region wird beim Spielstart festgelegt.
- **Was genau geschrieben wird:** Nur ein eigener, markierter Abschnitt („DbD Map Scout: server regions“). Vor der ersten Änderung wird die Originaldatei als `hosts.dbdmapscout-backup` daneben gesichert. Einträge von „Make Your Choice“ oder anderen Tools für dieselben Server werden beim Anwenden entfernt, weil sie die Auswahl sonst überschreiben würden. Das Programm fragt vorher nach.
- **Ping:** Gemessen wird wie bei Make Your Choice per normalem Ping (ICMP) an den GameLift-Dienst der Region (`gamelift.<region>.amazonaws.com`) – die Zeit misst Windows selbst, eine ausgelastete Bilderkennung verfälscht sie nicht. Antwortet er nicht, über den UDP-Ping-Beacon von GameLift (Port 7770). Die Namen werden direkt beim DNS-Server aufgelöst, deshalb gibt es auch für gesperrte Regionen einen Wert. Gemessen wird nur, wenn der Tab offen ist oder du „Ping messen“ drückst.
- **Grenzen:** Mit VPN unzuverlässig. Anders als der „Enforced“-Modus von Make Your Choice setzt das Programm keine Firewall-Regeln. DBD kann deshalb in seltenen Fällen trotzdem auf eine andere Region ausweichen, meist N. Virginia. Die Sperren bleiben aktiv, auch wenn das Programm geschlossen ist. Beim Start meldet das Log, wenn Regionen gesperrt sind.
- **Nicht übernommen** aus Make Your Choice: Firewall-Modus, eigener Splash-Screen und Trailer überspringen (verändern Spieldateien), Warteschlangen-Anzeige über den Fremddienst Dead by Queue.

### Verbundener Spielserver („Connected to“)

Mit dem Häkchen **Verbundenen Spielserver anzeigen** im Tab Server zeigt das Programm, mit welchem Server DBD gerade verbunden ist, z. B. „Verbunden mit: Frankfurt (3.120.45.67)“. Zwischen den Matches steht dort „Warte auf Match …“. Die Anzeige erscheint auch im Hauptfenster unter dem Rundentimer und im Overlay unter dem Timer als grüner Punkt mit der Region („● FRANKFURT“, ohne IP, abschaltbar im Tab Overlay), darunter der Ping („PING 24 MS“, grün bis 60 ms, gelb bis 120 ms, rot darüber), und das Log meldet jeden neuen Server mit seiner Region. Liegt er außerhalb deiner Regionsauswahl, steht das dabei. Die IP-Adresse steht nur live im Fenster und wird nicht ins Logfile geschrieben.

- **Administratorrechte:** Das Mitlesen des Netzwerkverkehrs braucht sie. Startest du das Programm als Administrator, läuft es ohne Nachfrage. Sonst fragt Windows bei jedem Programmstart einmal nach, solange das Häkchen gesetzt ist.
- **Was gelesen wird:** Nur die Kopfdaten der Netzwerkpakete (IP-Adressen und Ports), nie deren Inhalt. Es kommt nur der Verkehr deines eigenen PCs an: Die Netzwerkkarte wird nicht in den Promiscuous-Modus versetzt, der auch fremde Pakete im Netz annimmt. Unterstützt Windows das nicht, bleibt die Anzeige aus, statt auf diesen Modus auszuweichen. Es wird nichts gesendet, nichts verändert und nichts gespeichert. Das Spiel wird dabei nicht angefasst, und es braucht keinen Zusatztreiber wie Npcap.
- **Wie der Server erkannt wird:** Ein laufendes Match tauscht ständig viele UDP-Pakete mit seinem Server aus. Die Region steht im Namen, den AWS für die Server-Adresse vergibt (Reverse-DNS, z. B. `…eu-central-1.compute.amazonaws.com`). Andere Programme mit viel UDP-Verkehr wie Sprachchat werden ignoriert, weil sie nicht auf AWS-Servern laufen.
- **Ping:** Gemessen wird wie im Tab Server: alle 5 Sekunden ein Ping an den GameLift-Dienst der verbundenen Region, angezeigt wird der Mittelwert (Median) der letzten drei Messungen. Der Spielserver selbst bekommt keine Pakete. Er steht im selben Rechenzentrum, der Wert entspricht also praktisch dem Spiel-Ping.
- **Sparsam:** Läuft DBD 30 Sekunden nicht (z. B. während eines Downloads), pausiert der Mitschnitt und startet automatisch wieder, sobald DBD läuft – nur wenn das Programm als Administrator läuft, sonst würde jeder Neustart eine Windows-Abfrage auslösen.
- **Grenzen:** Mit VPN kann die Anzeige fehlen. Ohne Administratorrechte, zum Beispiel bei einer abgelehnten Windows-Abfrage, bleibt sie aus.
- **„Region unbekannt“:** Seit Herbst 2026 laufen manche DBD-Server in einem AWS-Adressbereich (54.115.x.x), für den AWS keine Region verrät – weder per Reverse-DNS noch in der offiziellen Adressliste (dort „GLOBAL“). Das Programm zeigt dann „Region unbekannt“ und keinen Ping. Auch wenn im Tab Server nur eine Region erlaubt ist, rät das Programm sie nicht: In der Gruppe eines Freundes entscheidet dessen Matchmaking, wo gespielt wird (bis 1.41.4 stand dann fälschlich die eigene Region da). Den Spielserver selbst anzupingen wäre möglich, ist aber bewusst ausgeschlossen (keine Pakete an den Spielserver).
- **Bleibt es bei „Warte auf Match …“:** Nach einem Match „Diagnose kopieren“ drücken. Unter „Verbunden mit“ stehen die Gegenstellen mit dem meisten UDP-Verkehr der letzten 30 Minuten (Pakete pro Sekunde, Port, Reverse-DNS-Name), die Adressen dabei unkenntlich gemacht. Daran sieht man, ob der Spielserver gar nicht im Mitschnitt auftaucht oder keinen AWS-Namen mehr hat.
- **Am sichersten:** Das Programm normal starten statt als Administrator, dann läuft nur der kleine Mitschnitt-Helfer mit Adminrechten (eine Windows-Abfrage pro Start). Wer ganz auf Nummer sicher gehen will, lässt das Häkchen aus – für Map-Erkennung und Overlay wird der Mitschnitt nicht gebraucht.

## So funktioniert die Erkennung

1. Etwa 5× pro Sekunde wird nur der Bereich unten links des DBD-Fensters aufgenommen, wie bei einer Bildschirmaufnahme. Ist die Map erkannt und das Match läuft, sinkt das auf 1× pro Sekunde (spart Leistung für das Spiel); nach dem Rundenende geht es wieder auf den vollen Takt.
2. Gesucht wird die **dünne Trennlinie** zwischen Map-Name und Realm. Sie ist ein sehr eindeutiges Merkmal und kostet nur wenige Millisekunden. Solange sie nicht zu sehen ist, läuft keine OCR.
3. Ist sie da, werden die Textzeile darüber (Map-Name, auch zweizeilig) und darunter (Realm) genau ausgeschnitten. Das funktioniert unabhängig von Auflösung, UI-Skalierung und Monitorformat.
4. Ein Texterkennungsmodell (PaddleOCR PP-OCRv4, läuft lokal) liefert pro Buchstabe Wahrscheinlichkeiten. Statt daraus Text zu raten, wird für **jeden bekannten Map-Namen berechnet, wie wahrscheinlich genau dieser Name ist**, zusammen mit dem Realm. Deshalb stören Hintergrund, Nebel und Apostrophe kaum, und „COAL TOWER“ lässt sich von „COAL TOWER II“ unterscheiden.
5. Die Ergebnisse mehrerer Bilder werden kombiniert. Unbekannter Text (z. B. eine neue Map ohne Bild) wird nicht auf eine falsche Map abgebildet, sondern im Log gemeldet.

**Unbekannte Map zuordnen.** Liest das Programm einen Map-Namen, den es nicht kennt (z. B. nach einem DBD-Update oder bei anderer Schreibweise), erscheint im Hauptfenster „Unbekannte Map gelesen: „…““ mit dem Knopf **Zuordnen …**. Dort die richtige Map wählen (ein Vorschlag ist vorausgewählt) – der gelesene Name wird ab sofort erkannt. Die Zuordnungen stehen in `settings.json` und bleiben bei Updates erhalten; der Realm wird weiterhin geprüft. Löschen unter **Einstellungen → Eigene Map-Zuordnungen**.

Hinweis zu Varianten: Seit Patch 8.6.0 sind die II/III-Layouts (MacMillan II, Ormond II/III, Badham II–V) nur noch in Custom Games spielbar. Bei unsicherer Lesung wird deshalb leicht das Standard-Layout bevorzugt. `Strg+Alt+V` oder der Layout-Knopf wechselt manuell.

### Wie gut ist die Erkennung?

Getestet mit echten DBD-Screenshots und mit nachgebauten Map-Bannern auf echten Spielhintergründen. Nachgebaut heisst: Roboto-Schrift, Geometrie von echten 4K-Screenshots abgemessen, EN/DE, Nebel, Schnee, Einblend-Animation.

| Test | Ergebnis |
|---|---|
| echte Banner-Screenshots (2 Maps × 5 Auflösungen × 2 Hintergründe) | 20/20 richtig |
| alle 56 Bilder × EN/DE, gemischte Auflösungen 720p–4K + Ultrawide | 112/112 richtige Map inkl. Layout |
| dasselbe mit sehr unruhigen Hintergründen | 112/112 richtige Map, 1× falsches Layout (Badham II → I) |
| Bildschirme ohne Banner (Lobby, Menüs, Gameplay, Endscreen) | 0 Fehlalarme bei 319 Bildern |
| Banner mit unbekannten Map-Namen | 0 von 120 fälschlich einer Map zugeordnet |
| Vergleich mit dem Ansatz von dbd-map-overlay (nachgebaut), 1440p, einzelnes Bild mit voll sichtbarem Banner | 55/56 statt 44/56, ca. 0,1 s statt 1,5–3 s pro Bild |

Die synthetischen Tests ersetzen keinen Praxistest. Wenn eine Map in echten Runden nicht erkannt wird, helfen die Debug-Bilder (siehe unten) beim Nachschärfen.

## Eigene / neue Karten

- **Eigenes Kartenbild (empfohlen):** Tab Maps → „Kartenbild hinzufügen …“ (oder nach einem nicht erkannten Banner „Bild hinzufügen …“). Bild wählen, dann entweder das Bild einer vorhandenen Map ersetzen oder eine neue Map anlegen (Name so, wie er im Banner steht, und Realm). Das Programm schneidet den Rand ab, macht den Hintergrund der Community-Karten (Dunkelblau `#282a42`, Graulila `#535781`, 10 % Toleranz) transparent, bringt das Bild auf 1280 px Höhe und speichert es als WebP in `user_maps/`. Mit „Map-Namen oben einfügen“ (standardmäßig an) schreibt es den Namen wie bei den mitgelieferten Karten über die Karte (weiss mit Schatten, Schrift Fira Sans ExtraBold); hat das Bild oben schon einen Namen, bleibt es dabei. Eine Vorschau zeigt vorher/nachher. Animierte GIFs werden unverändert übernommen. `user_maps/` wird von Git ignoriert, das Update beim Start funktioniert also weiter. Eigene Bilder haben Vorrang vor den mitgelieferten; „Eigenes Bild löschen“ stellt das Original wieder her.
- **Neues Bild von Hand ergänzen:** Datei in einen Unterordner von `user_maps/` (oder `maps/`) legen, benannt nach dem Map-Namen, wie er im Spiel steht, z. B. `user_maps/Neuer Realm/Neue Map.png`. Das Programm erkennt sie dann automatisch (englischer Name bzw. der Name aus der Datei). Bilder in `maps/` gelten als eigene Änderung und halten das automatische Update an.
- **Bild austauschen:** Datei in `maps/` ersetzen oder in `maps.json` den Pfad unter `variants` ändern.
- **Zusätzliche Schreibweise:** in `maps.json` bei der Map `"aliases": ["ANDERER NAME"]` ergänzen.

## Wenn etwas nicht klappt

- **Karte ist nicht zu sehen:** Im Tab Overlay „Overlay testen“ drücken. Die Karte erscheint dann 10 Sekunden lang an ihrer normalen Position, auch wenn sie sonst gerade ausgeblendet wäre (nochmal drücken – „Test beenden“ – blendet sie sofort wieder aus). War vorher keine Karte eingeblendet, ist nach dem Test auch wieder keine zu sehen. Bleibt sie unsichtbar, „Diagnose kopieren“ drücken und den Text weitergeben. Er enthält Fensterposition, Fensterstil und Z-Reihenfolge gegenüber DBD.
- **Map wird nicht erkannt:** Im Steuerfenster „Debug-Bilder speichern“ aktivieren und ein Match starten. Im Ordner `debug/` landen dann die Bilder, die das Programm gesehen hat, samt gelesenem Text.
- **Karte verschwindet nach der Runde nicht:** Im Tab Erkennung auf die Zeile „Rundenende-Erkennung“ schauen. Direkt danach „Diagnose kopieren“ drücken: Der Text enthält die letzten Prüfungen (was bei „CONTINUE“, Währung und Ladebalken gelesen wurde und ob der Mauszeiger sichtbar war). Mit „Debug-Bilder speichern“ landen während der Runde außerdem verkleinerte Bildschirmfotos in `debug/frames/`.
- **Eigene Screenshots testen:** Screenshots mit sichtbarem Map-Banner (Win+Druck) auf `screenshot_testen.bat` ziehen. Das Fenster zeigt dann, was erkannt wird.
- **Fehlermeldungen sehen:** `start_debug.bat` startet mit Konsole. Ausserdem gibt es die Protokolldatei `dbdmapscout.log`.
- **„Aufnahme ist schwarz“:** DBD auf „Fenster-Vollbild“ stellen. Bei aktiviertem Windows-HDR kann die Aufnahme ebenfalls Probleme machen.
- **Hotkey geht nicht:** Das Log meldet, wenn ein anderes Programm die Kombination belegt. In `settings.json` eine andere wählen.
- **Fenster ruckelt / reagiert verzögert:** Direkt danach „Diagnose kopieren“ drücken. Am Ende stehen die „Fenster-Hänger“: jeder Takt oder Klick, der 30 ms oder länger dauerte oder sich verspätete, mit Uhrzeit und Namen. Daran lässt sich die Ursache finden.

## Regeln / Fair Play

Das Programm wurde bewusst so gebaut, dass es **nicht mit dem Spiel interagiert**:

- keine Tastatur- oder Mauseingaben ans Spiel, keine Automatisierung von Spielaktionen,
- kein Zugriff auf den Spielprozess (kein Speicherlesen, keine Injection, nicht einmal ein Prozess-Handle), keine Netzwerkverbindung zum Spiel,
- keine Spieldateien werden gelesen oder verändert,
- die **Systemwerte** kommen vom NVIDIA-Treiber (nur Gerätewerte, keine Prozesslisten), von HWiNFO (falls es läuft) und von Windows selbst – kein eigener Treiber,
- gelesen werden nur Bildschirmpixel (wie bei OBS/Discord) und ob der Windows-Mauszeiger gerade sichtbar ist (dieselbe Systeminfo, mit der OBS den Zeiger in Aufnahmen zeichnet). Genutzt wird nur der Map-Name, den das Spiel allen anzeigt,
- angezeigt wird eine statische Community-Karte, keine versteckten Informationen (keine Generatoren, keine Positionen),
- Map-Erkennung und Overlay bauen keine Internetverbindung auf (Updates: nur im Starter und auf Knopfdruck „Jetzt nach Updates suchen“, nur GitHub), die Texterkennung läuft komplett lokal. Nur der Tab **Server** misst auf Wunsch den Ping zu den GameLift-Servern von AWS.
- Die **offiziellen Match-Daten** (Kills, Escapes, Bloodpoints) liest das Programm nur aus einer Datei, die dein Browser von der offiziellen Stats-Seite speichert (eigenes Userscript), und löscht sie danach. Auf Wunsch öffnet das Programm die Seite im Browser, wenn DBD beendet wurde – das Programm selbst baut dafür keine Verbindung auf.
- Der Tab **Server** verändert nicht das Spiel, sondern die Windows-hosts-Datei. Das ist eine Systemeinstellung, die für den ganzen PC gilt und jederzeit mit „Alles freigeben“ rückgängig gemacht werden kann. BHVR hat Region-Tools wie „Make Your Choice“ weder offiziell erlaubt noch verboten. Auch hier gilt: Nutzung auf eigene Verantwortung.

BHVRs [Game Rules](https://forums.bhvr.com/dead-by-daylight/kb/articles/139-game-rules) verbieten Drittsoftware, die einen „unfair advantage that wasn't intended by the game“ verschafft, sofern sie nicht freigegeben ist. Eine offizielle Freigabe für Map-Overlays gibt es nicht. Die Entscheidung liegt bei BHVR, Nutzung auf eigene Verantwortung. In Turnieren oder Ligen gelten deren eigene Regeln.
