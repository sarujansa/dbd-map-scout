# Fog Scout

*[Deutsche Fassung: README.md](README.md)*

Map overlay for Dead by Daylight. When a match starts, the map name is detected automatically and the matching callout map from the `maps/` folder is shown. The map is a separate click-through window on top of the game.

**Language:** the program shows German or English. By default it follows the Windows language (English unless Windows runs in German). Change it under **Settings → Language and appearance → Sprache / Language**; it takes effect the next time the program starts.

**Renamed (1.9):** until 1.8.91 the program was called "DbD Map Scout" – another program carries that name, so it is **Fog Scout** now (program folder `fogscout/`). The update handles the switch itself: scheduled tasks and shortcuts (now "Fog Scout", the old ones are removed; if the program was pinned to the taskbar, pin it once more), the program's own OBS sources (renamed in OBS, not created twice), its own section in the hosts file with its backup, the recording indexes in the recording folder, and `fogscout.log`/`fogscout-crash*.txt` in the program folder. Settings and statistics (`settings.json`, `rounds.jsonl`, `official.jsonl`) stay as they are. **To do yourself:** paste the userscript again – version 5 is called "Fog Scout – match export" and saves `fogscout-matches.json`; delete the old "DbD Map Scout – match export" in Tampermonkey, otherwise both save a file (the program still reads old files). You may rename the program folder (e.g. `fog-scout`): afterwards run `start.bat` once as administrator (right-click), as when moving the folder.

## Installation (once)

1. **Install Python** (if you do not have it yet): <https://www.python.org/downloads/>, version **3.12 to 3.14** (onnxruntime and pywinrt are not available for 3.15 yet; a newer version may stay installed alongside, `start.bat` picks the right one). Tick **"Add python.exe to PATH"** in the installer.
2. Unpack the folder, e.g. to `C:\Tools\fog-scout`.
3. Double-click **`start.bat`**. The first start creates a Python environment of its own (`.venv`) and installs the packages (about 1–2 minutes, around 250 MB; since 1.8.53 always exactly the tested versions from `requirements.txt`, never newer ones by themselves). The program then starts right away.
4. **Desktop shortcut:** once the program runs as administrator (e.g. right-click `start.bat` → "Run as administrator"), it sets the shortcut up **by itself** and renews it after updates or when you move the folder. By hand: **`verknuepfung_erstellen.bat`** (Windows asks once for administrator rights). Both create the task "Fog Scout" in the Windows Task Scheduler and put "Fog Scout" with its own icon on the desktop: the shortcut starts the program as administrator (needed for "Connected to") **without a Windows prompt** and without a console window. The same shortcut goes into the **Start menu**. Pin it via the shortcut (right-click → "Pin to taskbar") or directly on the running program in the taskbar – either way it is one button with the program icon. (Pinned before 1.30.3 and it shows the Python icon? "Unpin from taskbar" once, start the program once through the desktop shortcut, pin again.)

**Notification area and autostart.** When minimised, the control window goes to the notification area next to the clock (double-click opens it, right-click: overlay on/off, quit). Since 1.3.6 a coloured dot on the icon shows where things stand: grey = DBD runs, waiting for the next map, green = map on display, yellow = map detected with doubt, red = a problem (e.g. black capture); no dot = DBD is not running. The program **starts with Windows** (on by default since 1.30.3, set up on the first start as administrator or through the desktop shortcut) – quietly in the notification area, as administrator, without a prompt. Without DBD it only looks for the game window once a second; as soon as DBD runs, it works. Starting exactly "when DBD starts" is not possible within the rules (something would have to watch processes or launch the game). If it is already running (also hidden in the notification area), starting it again only says "already running". Switch it off under **Settings → Start and notification area** – it then stays off. Switching works when the program runs through the desktop shortcut.

*Security note:* a task "with highest privileges" deliberately skips the Windows prompt – whatever is in the program folder (including code fetched by an update) then runs as administrator without asking. If you want this stricter, put the folder somewhere only administrators can write to (e.g. under `C:\Program Files`).

**Updates** come automatically: when started through `start.bat` or the desktop shortcut, the program fetches the new version from GitHub (only if the folder is a git clone on `main` and you did not change program files yourself) and installs changed packages. Offline or with your own changes it simply starts the version that is there. The log shows what is new – and since 1.8.79 so does a card "New since …" at the top of the overview (the rows of `HISTORY.md` since the version last run, until "Got it"). Can be switched off under **Settings → Updates**. There is also **"Check for updates now"**: it asks GitHub (only on this click) and shows "No update" or the new version with its changes; **"Update and restart"** closes the program, installs the update via `start.bat` and starts again – even if the check at start is switched off. Since 1.8.63 this is **locked during a round** (map detected, no round end yet, or OBS still recording): only a note appears, click again after the round ends. Since 1.65.1 the program surely ends completely when closed (before, an invisible copy could stay behind – then it did not come back after an update and said “already running”). Starting it while it sits in the notification area brings the running copy's window to the front; if that copy does not answer, a message says what to do.

In DBD, use the display mode **"Windowed Fullscreen"** under **Settings → Graphics**. In exclusive fullscreen Windows cannot show a window on top of the game.

**Window mode** works too: the map then appears next to the DBD window if at least 200 px of the monitor are free there, and the background window capture leaves out the title bar. Below 1920×1080 detection is less reliable (above all the lobby button and killer name). Windows narrower than 16:9 (e.g. 1718×1360): DBD shows the match there with black bars above and below, the game picture is only about 850 px high. Since 1.44.1 the map name is read there too (the thin line below the name is very faint in such a small picture); since 1.8.61 the lobby button (search, lobby, killer name, countdown, cross-play) is read there as well: DBD shrinks the menus to the window width and keeps the button at the bottom edge – before, the program looked for it too high and found no lobby (wait, role, killer and farming were then missing from the statistics). Round end is less tested in this format. Since 1.8.62 the map name is read there even when the thin line below it is invisible on a bright floor (RPD tiles): at the banner's fixed spot, counted only when the name fits cleanly. (In 1.8.62–1.8.64 this did not run: the program took the picture for letterboxed only once a map was already on display – since 1.8.65 it also looks at a narrow strip in the middle once a second when there is none.) **Overlay in small windows** (since 1.8.62, box on the Overlay page → General, on by default): if the DBD picture is smaller than 1920×1080 or narrower than 16:9, the program shows nothing in the game – map detection, statistics and OBS recordings go on; in a big window the overlay comes back by itself. **Since 1.45 Fog Scout uses these bars:** the map then goes into the bottom bar (since 1.45.1 also with a custom position – that applies again as soon as there are no bars above/below, e.g. in fullscreen) (left, timer/server right of it), the system values into the top bar. The bars are measured in the running picture (during the intro with the map name they are higher than in gameplay). Lobby and menus have no bars, the normal placement applies there. The map is as big as the bar is high – about 170 px at 1718×1360. The log mentions both once.

## Usage

On the **first start** a short **setup** (since 1.60) goes through four steps: game language, overlay position (with "Test overlay"), the most important keys and since 1.2.15 the match data (userscript for the stats page) – "Skip" works any time, open it again under Settings → Start and notification area → "Start setup". **Search:** the field above the navigation (Ctrl+F) finds any setting on all pages, jumps there and lights up its box for a moment.

Start the program and play DBD. When the map name appears at the bottom left at the start of a match (e.g. "COAL TOWER / THE MACMILLAN ESTATE"), the map is shown automatically.

**After the round** the map disappears again. This is detected by:

- the results screen (button "CONTINUE"),
- lobby, main menu, bloodweb and store (currencies at the top right),
- the loading screen of the next round (almost black, still picture with a loading bar – lying on the ground with the recovery bar does not count),
- DBD being closed.

On ultrawide monitors DBD shows the results screen and menus in full width, but the match in 16:9 with black bars. The program recognises this and then looks for CONTINUE and the currencies up to the real screen edge; during the match the bars are left out.

**The overlay pauses in menus.** DBD only shows the mouse pointer in menus (ESC menu, results screen, lobby). If it is visible over the DBD window for a few seconds, the map is hidden. When it disappears, the map comes back. If the mouse pointer is visible in a menu for a minute in total, the round counts as over.

**Round timer.** The timer runs while a map is shown. When a map appears (detected automatically, chosen by hand or shown by hotkey), it starts at 00:00. When it disappears (end of round detected or hidden by hand), it stops. It is shown in the control window below the map name ("Round running: 07:32", then "Last round: 12:04") and large and centred right below the map in the overlay, styled like the map title: white digits with a shadow, no box (can be switched off in the Overlay tab). At the end of the round, the first sign of it counts as the end time, e.g. the mouse pointer appearing on the results screen, not the moment detection is sure. Briefly hiding in the ESC menu or while another window is active does not stop the timer, because the match goes on. Switching the layout or map while the map is shown does not reset it. A new map banner always starts a new round, even if the end of the previous one was not detected.

**Waiting card.** While DBD runs and no map is shown (before the match, in the lobby, after the round), the overlay shows a small card in the same place: "WAITING FOR MAP", below it the search or lobby ("SEARCHING: 02:13 · NURSE") or after the round "LAST ROUND: 12:04". With "Connected game server" (Server tab) on, region and ping follow below as soon as DBD is connected to a game server – usually from the lobby on. As soon as the map banner is detected, the map replaces it. If it is still there in the middle of a match, the map was not detected – use "Scan". Not when you hid the map yourself; can be switched off in the Overlay tab.

**Only while DBD runs.** As long as the DBD window is not found, nothing is detected automatically, even if a DBD video or screenshot is on screen. So no map pops up while you work. "Scan" still checks the main screen when clicked.

On the **Log** page under "Advanced", the line "End-of-round detection: …" always shows what the program currently sees, e.g. "in match · mouse pointer hidden". `Ctrl+Alt+M` brings back a hidden map right away.

The top of the control window always says where things stand: **Waiting for DBD**, **Waiting for the next match**, **In match: …**, **In a menu – map paused** or **Round over** (problems such as a black picture are shown in red). Technical details are in the Log tab.

**Info texts:** rest the mouse briefly on a button or checkbox and a small text explains what it does (with its hotkey).

**Layout button:** only appears for maps with several layouts (Coal Tower, Groaning Storehouse, Ironworks of Misery, Shelter Woods, Suffocation Pit, Mount Ormond Resort, Badham Preschool) and shows the layout on display, e.g. "Layout II of V ▸". A click switches to the next one. If detection was unsure about the layout, "(unsure)" is added.

After a new install or when the file got lost, this button (Settings → Match data → Official match data) opens the page so that the script saves the last 30 matches once more; known ones count once. Whether the script runs shows in the browser's console (F12): "[Fog Scout] userscript 4 active …" on loading and "no new match since the last file" when it saves nothing.

When the page opens, the script saves the matches as `fogscout-matches.json` into the download folder – only if a new match is among them, and only start time, map, custom game yes/no, role, character, status, length and BP (no names of other players, no account or login data; the script sends nothing anywhere). The program looks into the download folder every 20 s (every 3 s after opening the page), takes the matches into `official.jsonl` and **deletes the file** – a small notification bottom right says so ("30 matches read, 4 of them new. The file was deleted." and below it the new matches: "Killer: avg. 3.1 kills, 2× 4K (4)", escapes as survivor, bloodpoints – without custom games; not while DBD is in front; can be switched off under Settings → Match data → Official match data). **Own record in the overlay:** below the round timer it says how you have done on the detected map so far – as killer "Avg. 2.8 kills · 12 rounds", as survivor "40 % escaped · 9 rounds" (role from the lobby, otherwise the one played more often on that map; from 3 rounds with stats-page data; can be switched off in the Overlay tab). Files with that name but without the program's marker are left alone. Matches are tied to rounds by map and start time (the map banner comes about 30–50 s after the start on the page).

The statistics stay statistics of **your rounds** – the official data only adds to the rounds tied to a match. Below the number of rounds you see avg. kills, 4K and abandons as killer, the escape rate as survivor and the bloodpoints, each with the number of rounds they come from. The maps table adds avg. kills, escaped and avg. BP per map, the killer table avg. kills and 4K, "Last rounds" the column **Result** (3K / escaped / died / abandoned). For tied rounds the killer from the page counts (so outfits are right automatically), so does custom game and – if detection was wrong – the **map from the page** (layout I; since patch 8.6.0 other layouts exist only in custom games). Rounds whose end the program did not detect ("⚠ Not counted") count again as soon as there is a match for them – with the length from the page. **Abandoning** counts as a kill for the killer (like their result in the game) and as no escape for a survivor; the page itself shows some abandons as "Escaped" by mistake, the program recognises them by their icon. A survivor who left the match is no kill.

How well the program itself works is shown under **Settings → Match data → Official match data → Check against the stats page**: the detection rate ("Detected by the program: 29 of 30") with the latest matches it missed (map and time), how exactly the end of the round is detected (median against the end on the page) and notes for a **gap** (more than 30 matches between two visits of the page), a **different map than detected** and an **unknown status** (the page's status names are not documented; a new status does not count, please report it with "Copy diagnostics"). If the browser asks where to save each download, a dialog appears every time. If your download folder is elsewhere, set `official_dir` in `settings.json`.

**In the middle of a round** DBD never shows a map banner – but light strips or signs in the game world can look like one. From 30 s after the map appeared, the program therefore only switches maps if the "banner" stays still for at least 2 s and reads cleanly (a real banner after a missed end of round does). Anything else is only a line in the log ("Read … in the middle of the round – ignored"), and "Copy diagnosis" lists every sighting with the text read under "Letzte Banner". The program also keeps a picture of every such sighting in `debug/midmatch/` (even without "Save debug pictures"; only the newest 20, at most one every 10 s) – so you can see what it took for a banner. Should it still switch maps mid-match, the statistics drop that round as soon as the stats-page data is there: a second "round" in the middle of a match that already has one does not count ("✓ 1 × map read wrongly in the middle of a match …"). Without that data: select the round under "Last rounds" → **Delete round**.

**Unsure detection:** real map banners fit a known name almost perfectly. If none of the frames read fits well (fit below −3), not even 2.5 s later, the overlay shows "? UNSURE – CTRL+ALT+X = WRONG" in amber below the map, and the main window shows a bar with **Wrong map** / **Correct**. "Wrong map" (or `Ctrl+Alt+X`, works for any automatically detected map) hides the map, resets the timer and does not count the round; the same banner does not show it again. If the banner reads cleanly a moment later, the note goes away by itself.

**Rotate the map:** the **Rotate ↻** button in the main window or `Ctrl+Alt+R` turns the map on display by 90° clockwise, so it lies the way you picture the map. The rotation is remembered per map (Overlay tab: "Reset for this map"). The map name above the map stays upright; numbers and labels inside the map turn with it because they are part of the picture. All supplied maps carry their name on top in the same style; only on Midwich (animated GIF with its own background) does the name turn with the map. A map that turns with the camera by itself is not possible: only the game knows the camera angle, and its memory is never read.

**Floors (Midwich):** Midwich has two floors; the overlay shows both one below the other, top above bottom. Each floor is as big as any other map – the overlay gets twice as tall for that (at most 90 % of the screen height); in the black bar of an ultrawide monitor the width is the limit anyway, so both fit there at full bar width. The **Floor ▸** button in the main window (only shown for maps with floors) or `Ctrl+Alt+F` switches: both → bottom → top → both; this lasts until the next map. The button shows what is on display ("Both floors" or "Floor 2 of 2"). If Midwich should start with the bottom floor only, switch off "Show the floors (Midwich) one below the other" in the Overlay tab. The program does not know which floor you are on (that would need the game's memory).

**Keep in the black bar** (Overlay tab, on by default): on ultrawide the map stays inside the bar it is in, whatever the position – "top/bottom left" in the left bar, "top/bottom right" in the right one, a custom position in the bar where it starts. If it is too wide, it is made smaller instead of reaching into the game picture (the text below it first; since 1.2.3 the right size is measured beforehand – before, the map grew and shrank in the bar several times a second). A map placed over the middle of the game on purpose stays as it is. Switch it off if the map may be bigger than the bar.

The overlay is a native Windows window of its own: always on top, click-through, and it never takes the focus away from the game.

**Detection while other windows cover DBD.** Normally the screen is captured – if another window lies over DBD, the program sees that window. So while DBD is not the active window, the program uses **Windows' window capture** (Windows Graphics Capture, the same technique as OBS "Window Capture"): Windows delivers the picture of the DBD window, whatever lies on top. The game is not touched. Once DBD has been active again for 5 seconds, it goes back to the lighter screen capture. Nothing works while minimised. Can be switched off in the Detection tab ("Also detect when other windows cover DBD"). `start.bat` installs the extra package once at the next start; if that fails, everything keeps working through screen capture. Windows only delivers a new window picture when something moves in the DBD window – in a quiet menu sometimes none comes. Then the program takes the screen, but only the parts no other window lies over (according to Windows' window list); covered parts are skipped instead of read. Before, a window over DBD (e.g. the program's own statistics) could be read as a map banner. The line "Aufnahme" (capture) in the diagnostics shows which source is in use, whether the last picture still came from the screen and how often a covered look was skipped.

**Backing up settings:** Settings → Backup → "Export settings …" saves everything (hotkeys, size and rotation per map, own map assignments, overlay, regions) to a file, "Import settings …" loads it again and restarts the program. The statistics are not part of it.

Hotkeys can be changed under **Settings → Hotkeys**: click the field and press the new combination (Esc cancels, Delete switches the hotkey off, "Defaults" resets all). Letters, digits and space need Ctrl or Alt so the hotkey does not block normal typing (and DBD); combinations used twice are refused. **A single key** works with F1–F12, the numpad (0–9, +, −), Pause, Scroll Lock, Insert, Home, End and Page Up/Down: such hotkeys only apply while DBD is the active window – in every other program the key works as usual. **System values:** during a match, CPU and GPU temperature, load, GPU power, VRAM and RAM are shown at the top of the black bar (temperature green/amber/red; CPU from 80/90 °C, GPU from 75/85 °C). Same font as the map names on the maps (Fira Sans ExtraBold), labels grey, values bright. Set in the Overlay tab → System values: top right (default), **right above the map** (moves with the map, also at a custom position; without room above, the map moves down or the values go below it; in a half-width window with bars above/below they stand right of the map in the bottom bar), top left (the map moves below it), **own position** or off. With "own position" the display can be dragged anywhere together with the map via "Move with the mouse" (Ctrl+Alt+P); the place is stored relative to the window; in a narrow window with bars above/below it stays in the top bar. GPU values come from NVIDIA cards through the driver (`nvml.dll`). The **CPU temperature** needs [HWiNFO](https://www.hwinfo.com/) with "Shared Memory Support" on (HWiNFO → settings; the free version needs it switched on again every 12 hours). Windows itself only tells the CPU temperature through a kernel driver – the program deliberately does not load one (anti-cheat, drivers blocked by Microsoft such as WinRing0). With HWiNFO there is also a GPU temperature for AMD/Intel graphics, plus a row with **hot spot** and **GPU memory** (memory junction) – the more critical values, they run 10–20 °C above the core (amber from 95 °C, red from 105 °C). When the **GPU throttles** because of temperature or hardware (NVIDIA), a red "GPU THROTTLED (TEMP.)" or "(HW)" appears. The normal power limit under full load does not count – for graphics cards that is the normal state. In the lobby and menus (DBD uses the full width there) the line is off. **Statistics → System:** for each round the program keeps the average and the highest value (GPU/CPU temperature, GPU load, power, VRAM, RAM; only while the display is on). That page shows the average of the selection, the highest values with date, time and map, and a table by map, time of day (3-hour blocks), weekday or killer – so you can see on which maps or at what time of day the PC runs hottest. The filters at the top (period, region, role, killer) apply here too. Also: columns hot spot max and "Throttled" (seconds), a note "GPU throttled in n of m rounds" and below it a **GPU temperature trend** (average per hour/day/week depending on the period; hovering a point shows average, maximum, hot spot and number of rounds). A line that slowly rises over weeks usually means dust, thermal paste or a fan. **Since 1.2.1 with HWiNFO for the CPU too:** if the CPU slows down because of heat (HWiNFO readings like "Thermal Throttling"/PROCHOT; power limits deliberately do not count, they are normal under load), a red "CPU THROTTLED (TEMP.)" appears. Statistics → System gets the tiles "Avg. busiest CPU core" (load of the busiest thread – DBD runs on few cores, "CPU 35 %" can be one core at 100 %), "Avg. CPU power" and "CPU throttled" (only rounds with HWiNFO), the same values as table columns and the highest CPU power. With the free HWiNFO they are missing once sharing ends after 12 hours. **Since 1.2.2 FPS too:** if HWiNFO shows a frame rate in its sensor window (PresentMon, "Framerate (Presented)"), the program keeps per round the average FPS and the **FPS low** = the slowest 1 % of the round's seconds (HWiNFO only gives averages per second, so it is not a true per-frame "1 % low"). Statistics → System: tiles Avg. FPS and Avg. FPS low, columns by map/time/killer – showing on which maps it stutters – and among the highest values the round with the lowest FPS low. **FPS stays empty?** (since 1.8.59) It is only counted while the system values are switched on in the overlay and HWiNFO runs. Besides "Framerate (Presented)" a frame rate under another name ("FPS", "Framerate [Avg]") counts too, never lows or frame times. "Copy diagnosis" lists every frame reading HWiNFO gives in the line "Systemwerte" ("FPS-Zeilen von HWiNFO=…") – "keine" there means HWiNFO itself measures no FPS (switch on PresentMon or RivaTuner in HWiNFO). Only what HWiNFO shares is read, never the game.

## Choosing the server region (like "Make Your Choice")

The **Server** tab lists all DBD server regions (AWS GameLift) with their current ping. Tick the regions you want to play on and press **Apply selection**. All other regions are blocked in the Windows **hosts file**: their server names then point to 0.0.0.0, DBD cannot reach them and only looks for matches in the allowed regions. **Allow all** removes the blocks again.

- **Administrator rights:** the hosts file is a Windows system file, so Windows asks when applying and when allowing all. Only this write runs with administrator rights, not the program itself (unless you start it as administrator or use the connected server display, see below).
- **Restart DBD afterwards.** The region is fixed when the game starts.
- **What exactly is written:** only a section of its own, marked "Fog Scout: server regions". Before the first change the original file is saved next to it as `hosts.fogscout-backup`. Entries of "Make Your Choice" or other tools for the same servers are removed when applying, because they would otherwise override the selection. The program asks first.
- **Ping:** measured like Make Your Choice does, with a normal ping (ICMP) to the region's GameLift service (`gamelift.<region>.amazonaws.com`) – Windows times it itself, so busy map detection cannot distort it. Without an answer, through GameLift's UDP ping beacon (port 7770). The names are resolved directly at the DNS server, so blocked regions get a value too. It only measures while the tab is open or when you press "Measure ping".
- **Limits:** unreliable with a VPN. Unlike the "Enforced" mode of Make Your Choice, the program sets no firewall rules. In rare cases DBD may therefore still fall back to another region, usually N. Virginia. The blocks stay active while the program is closed. At start the log reports when regions are blocked.
- **Not taken over** from Make Your Choice: firewall mode, custom splash screen and skipping trailers (these change game files), queue display through the third-party service Dead by Queue.

### Connected game server ("Connected to")

With the checkbox **Show which server DBD is connected to** in the Server tab, the program shows which server DBD is connected to, e.g. "Connected to: Frankfurt (3.120.45.67)". Between matches it says "Waiting for a match …". The display also appears in the main window below the round timer and in the overlay below the timer as a green dot with the region ("● FRANKFURT", without IP, can be switched off in the Overlay tab), below it the ping ("PING 24 MS", green up to 60 ms, yellow up to 120 ms, red above), and the log reports every new server with its region. If it is outside your region selection, that is noted. The IP address is only shown live in the window and never written to the log file.

- **Administrator rights:** reading the network traffic needs them. If you start the program as administrator, it runs without asking. Otherwise Windows asks once per program start while the checkbox is ticked.
- **What is read:** only the headers of the network packets (IP addresses and ports), never their contents. Only your own PC's traffic arrives: the network card is not put into promiscuous mode, which would also accept other devices' packets. If Windows does not support this, the display stays off instead of falling back to that mode. Nothing is sent, nothing is changed and nothing is stored. The game is not touched, and no extra driver such as Npcap is needed.
- **How the server is found:** a running match constantly exchanges many UDP packets with its server. Since 1.11.6 only connections over DBD's own network ports count: Windows keeps a table of which program owns which port (the same one `netstat -abno` shows), and the program finds DBD by its window. The game process is not opened and nothing is read from it. Another program on AWS servers can no longer show up as the game server. The region is part of the name AWS gives the server address (reverse DNS, e.g. `…eu-central-1.compute.amazonaws.com`). Without the DBD window or a readable table the program takes the busiest UDP partner on an AWS server as before.
- **"Global"** (up to 1.64.5 "region unknown"): since autumn 2026 some DBD servers run in an AWS address range (54.115.x.x) whose region AWS does not reveal – neither by reverse DNS nor in its official address list (there: "GLOBAL"). The program then shows "Global" (as AWS names the range) and no ping. Even if only one region is allowed in the Server tab, the program does not guess it: in a friend's party their matchmaking decides where you play (up to 1.41.4 your own region was then shown by mistake). Pinging the game server itself would work but is ruled out on purpose (no packets to the game server).
- **Stuck at "Waiting for a match …":** after a match, press "Copy diagnostics". Under "Verbunden mit" it lists the partners with the most UDP traffic of the last 30 minutes (packets per second, port, reverse DNS name), with the addresses masked. That shows whether the game server is missing from the capture or no longer has an AWS name.
- **Ping:** measured like in the Server tab: every 5 seconds a ping to the GameLift service of the connected region; shown is the median of the last three measurements. The game server itself receives no packets. It is in the same data centre, so the value practically equals the game ping.
- **Economical:** if DBD has not been running for 30 seconds (e.g. during a download), the capture pauses and restarts automatically once DBD runs – only when the program runs as administrator, since otherwise every restart would trigger a Windows prompt.
- **Limits:** with a VPN the display may be missing. Without administrator rights, e.g. after a declined Windows prompt, it stays off.
- **Safest:** start the program normally instead of as administrator; then only the small capture helper runs with admin rights (one Windows prompt per start). If you want to be completely on the safe side, leave the checkbox off – map detection and overlay do not need the capture.

## How detection works

1. About 5 times per second, only the bottom-left area of the DBD window is captured, like a screen recording. Once the map is detected and the match is running, this drops to once per second (saving performance for the game); after the end of the round it goes back to the full rate.
2. It looks for the **thin dividing line** between map name and realm. It is a very distinctive feature and costs only a few milliseconds. As long as it is not visible, no OCR runs.
3. If it is there, the line of text above it (map name, also on two lines) and below it (realm) are cut out precisely. This works regardless of resolution, UI scale and monitor format.
4. A text recognition model (PaddleOCR PP-OCRv4, running locally) gives probabilities per letter. Instead of guessing text from them, the program **computes for every known map name how likely exactly that name is**, together with the realm. That is why background, fog and apostrophes hardly matter, and "COAL TOWER" can be told apart from "COAL TOWER II".
5. The results of several pictures are combined. Unknown text (e.g. a new map without a picture) is not mapped to a wrong map but reported in the log.

**Assigning an unknown map.** If the program reads a map name it does not know (e.g. after a DBD update or with a different spelling), the main window shows "Unknown map read: "…"" with the button **Assign …**. Choose the right map there (a suggestion is preselected) – the name read is recognised from then on. The assignments are stored in `settings.json` and survive updates; the realm is still checked. Delete them under **Settings → Own map assignments**.

Note on variants: since patch 8.6.0 the II/III layouts (MacMillan II, Ormond II/III, Badham II–V) can only be played in custom games. With an unsure reading, the standard layout is therefore slightly preferred. `Ctrl+Alt+V` or the layout button switches by hand.

## Own / new maps

- **Own map picture (recommended):** Maps tab → "Add map picture …" (or "Add picture …" after an unrecognised banner). Choose a picture, then either replace the picture of an existing map or create a new map (name as shown in the banner, and realm). The program cuts off the border, makes the background of the community maps (dark blue `#282a42`, grey violet `#535781`, 10 % tolerance) transparent, scales the picture to 1280 px height and saves it as WebP in `user_maps/`. With "Put the map name on top" (on by default) it writes the name above the map like on the supplied maps (white with a shadow, font Fira Sans ExtraBold); if the picture already has a name on top, it stays as it is. A preview shows before/after. Animated GIFs are used unchanged. `user_maps/` is ignored by git, so the update at start keeps working. Own pictures take precedence over the supplied ones; "Delete own picture" restores the original.
- **Adding a picture by hand:** put the file into a subfolder of `user_maps/` (or `maps/`), named after the map name as shown in the game, e.g. `user_maps/New Realm/New Map.png`. The program then recognises it automatically (English name or the name from the file). Pictures in `maps/` count as your own changes and stop the automatic update.
- **Replacing a picture:** replace the file in `maps/` or change the path under `variants` in `maps.json`.
- **Additional spelling:** add `"aliases": ["OTHER NAME"]` to the map in `maps.json`.

## When something does not work

- **The map is not visible:** press "Test overlay" in the Overlay tab. The map then appears for 10 seconds at its normal position, even if it would be hidden right now (press again – "End test" – to hide it at once). If no map was shown before, none is shown after the test either. If it stays invisible, press "Copy diagnostics" and pass the text on. It contains window position, window style and Z-order relative to DBD.
- **The map is not detected:** tick "Save debug pictures" in the control window and start a match. The folder `debug/` then receives the pictures the program saw, with the text it read.
- **The map does not disappear after the round:** look at the line "End-of-round detection" on the Log page under "Advanced". Right afterwards press "Copy diagnostics": the text contains the latest checks (what was read for "CONTINUE", currencies and loading bar, and whether the mouse pointer was visible). With "Save debug pictures", small screenshots from the round are also saved in `debug/frames/`.
- **Testing your own screenshots:** drag screenshots with a visible map banner (Win+Print) onto `screenshot_testen.bat`. The window then shows what is detected.
- **Seeing error messages:** `start_debug.bat` starts with a console. There is also the log file `fogscout.log`.
- **"Capture is black":** set DBD to "Windowed Fullscreen". Windows HDR can also cause capture problems.
- **A hotkey does not work:** the log reports when another program uses the combination. Choose another one under Settings → Hotkeys.
- **The window stutters / reacts late:** right afterwards press "Copy diagnostics". At the end it lists the "window hangs": every tick or click that took or was late 30 ms or more, with time and name – that shows the cause.

## Rules / fair play

The program was deliberately built so that it **does not interact with the game**:

- no keyboard or mouse input to the game, no automation of game actions,
- no access to the game process (no memory reading, no injection, not even a process handle), no network connection to the game,
- no game files are read or changed,
- the **system values** come from the NVIDIA driver (device values only, no process lists), from HWiNFO (if it runs) and from Windows itself – no driver of our own,
- only screen pixels are read (like OBS/Discord) and whether the Windows mouse pointer is currently visible (the same system information OBS uses to draw the pointer in recordings). Only the map name the game shows to everyone is used,
- a static community map is shown, no hidden information (no generators, no positions),
- map detection and overlay open no internet connection (updates: only in the starter and on the "Check for updates now" button, GitHub only), text recognition runs completely locally. The built-in Microsoft telemetry of the OCR library onnxruntime is switched off by the program (since 1.64.7; before, onnxruntime tried to send usage data to Microsoft). Only the **Server** tab measures the ping to AWS GameLift servers on request.
- **Discord** (since 1.7, only when switched on): the program tells the Discord client on this PC over its local pipe what is going on (map, role, killer, lobby, start time) – the way games report their "Rich Presence". No internet connection from the program, nothing is read from Discord.
- **Spotify** (since 1.8, only when switched on): the program asks Spotify (Web API, internet) for your queue – read only, only while the music card is on screen, with a consent you give in the browser and can delete here any time. No control, nothing else of the account, no titles in the log.
- The **official match data** (kills, escapes, bloodpoints) only comes from a file your browser saves from the official stats page (own userscript) and deletes it afterwards. If you want, the program opens that page in the browser once DBD was closed – the program itself makes no connection for it.
- The **Server** tab does not change the game but the Windows hosts file. That is a system setting for the whole PC and can be undone at any time with "Allow all". BHVR has neither officially allowed nor forbidden region tools like "Make Your Choice". Here too: use at your own risk.

BHVR's [Game Rules](https://forums.bhvr.com/dead-by-daylight/kb/articles/139-game-rules) forbid third-party software that gives an "unfair advantage that wasn't intended by the game" unless it is approved. There is no official approval for map overlays. The decision is BHVR's, use at your own risk. Tournaments and leagues have their own rules.
